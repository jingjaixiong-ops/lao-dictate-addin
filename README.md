# Lao Dictate — ปลั๊กอินถอดเสียงภาษาลาวสำหรับ MS Word

Word Add-in (task pane) ที่ถอดเสียงภาษาลาวเป็นข้อความ 2 โหมด:

1. **Real-time (คำต่อคำ / ประโยคต่อประโยค) — ของจริง** ใช้ `SpeechRecognition` (Web Speech API) ในตัวเบราว์เซอร์/WebView เอง (`continuous: true`, `interimResults: true`, `lang: "lo"`) เบราว์เซอร์ตระกูล Chromium (Chrome/Edge) ส่งเสียงไปให้บริการถอดเสียงของ Google แบบสตรีมมิงและยิง event กลับมาเป็นคำ ๆ ระหว่างพูด (interim) แล้วยืนยันเป็นประโยคเมื่อพูดจบ (final) — เราแทรก **เฉพาะผลลัพธ์ final** ลงเอกสาร Word ทันที ส่วนคำที่กำลังฟังอยู่ (interim) จะโชว์แบบสดในกล่องตัวอย่างแต่ยังไม่ยืนยันลงเอกสาร วิธีนี้ **ไม่ต้องใช้ API key ไม่ต้องมีเซิร์ฟเวอร์ และไม่มีค่าใช้จ่ายต่อการเรียก**
2. **Upload ไฟล์เสียง** — เลือกไฟล์เสียง (mp3, wav, m4a, webm ฯลฯ) แล้วถอดความทั้งไฟล์ แทรกลงเอกสาร (ไม่ real-time) ใช้ OpenAI `whisper-1` (endpoint `/v1/audio/transcriptions`, `language=lo`) เป็นเอนจิน เหมาะสำหรับไฟล์ที่อัดไว้ล่วงหน้า หรือใช้เป็นทางเลือกสำรองบนแพลตฟอร์มที่ Web Speech API ใช้ไม่ได้ (เช่น Word for Mac)

### ทำไมโหมด 1 ถึง "real-time" จริง ๆ
เพราะรายชื่อภาษาที่ Google Speech Recognition (เอนจินเบื้องหลัง Web Speech API ของ Chrome/Edge) รองรับ **มีภาษาลาว (`lo`) อยู่ในรายการอย่างเป็นทางการ** จึงตั้ง `recognition.lang = "lo"` ได้ตรง ๆ โดยไม่ต้องพึ่งบริการเสริมหรือ backend ใด ๆ

### ข้อจำกัดของโหมด Real-time
- ใช้ได้เฉพาะบน **เอนจิน Chromium** เท่านั้น: Word desktop บน **Windows** (ใช้ WebView2 ซึ่งเป็น Chromium) หรือ Word บนเว็บที่เปิดผ่าน **Chrome/Edge** — Word for **Mac** ใช้ WKWebView (เอนจิน Safari) ซึ่ง **ไม่รองรับ** `SpeechRecognition` เลย ให้ใช้โหมด 2 (อัปโหลดไฟล์) แทนบน Mac
- ต้องมีอินเทอร์เน็ต เพราะเสียงถูกส่งไปประมวลผลบนคลาวด์ของ Google
- คุณภาพ/ความแม่นยำขึ้นกับเอนจินฟรีของ Google ซึ่งอาจไม่ปรับแต่งเฉพาะทางเท่าโมเดล paid อย่าง Whisper — ถ้าความแม่นยำไม่พอ ให้พิจารณาโหมด 2 หรือ Google Cloud Speech-to-Text (streaming) ผ่าน backend ของคุณเอง

## โครงสร้างไฟล์
```
manifest.xml     ← ไฟล์ manifest ของ Add-in (ต้องแก้ URL ก่อนใช้งานจริง)
taskpane.html    ← หน้า UI
taskpane.css     ← สไตล์
taskpane.js      ← ลอจิกทั้งหมด (บันทึกเสียง, เรียก API, แทรกข้อความ)
assets/          ← ไอคอน (เป็นไอคอนตัวอย่าง แนะนำให้เปลี่ยนเป็นของจริง)
```

## วิธีใช้งาน (ทดสอบ)

### 1) โฮสต์ไฟล์ผ่าน HTTPS
Word (ทั้ง desktop และ web) โหลด task pane ผ่าน HTTPS เท่านั้น วิธีที่เร็วที่สุดสำหรับทดสอบคือรันเซิร์ฟเวอร์ static บนเครื่องแล้ว expose ผ่าน HTTPS เช่น:

```bash
npx http-server . -p 3000 --ssl
# หรือใช้ ngrok เพื่อได้ URL https ชั่วคราว
npx http-server . -p 3000
ngrok http 3000
```

จากนั้นแก้ทุกจุดที่เป็น `https://YOUR-HOSTING-DOMAIN` ใน `manifest.xml` ให้เป็น URL จริงของคุณ

### 2) Sideload manifest เข้า Word
- **Word บนเว็บ**: Insert → Add-ins → Upload My Add-in → เลือก `manifest.xml`
- **Word desktop (Windows/Mac)**: ใช้วิธี "Shared Folder" catalog — วางไฟล์ manifest.xml ไว้ในโฟลเดอร์ที่แชร์แล้วเพิ่มโฟลเดอร์นั้นเป็น Trusted Add-in Catalog ใน Word (Options → Trust Center) รายละเอียดตามเอกสาร Microsoft: “Sideload Office Add-ins for testing”

### 3) ใส่ OpenAI API Key
เปิด task pane → ใส่ API key ของคุณ → กด "บันทึกคีย์" (เก็บใน `localStorage` ของเบราว์เซอร์/WebView ในเครื่องเท่านั้น)

## ข้อควรระวังสำคัญก่อนใช้งานจริงในองค์กร

1. **ความปลอดภัยของ API Key (เฉพาะโหมดอัปโหลดไฟล์)** — โหมด real-time ไม่ใช้คีย์เลย แต่โหมดอัปโหลดไฟล์เรียก OpenAI ตรงจากฝั่ง client เพื่อความง่ายในการทดสอบ ถ้าจะใช้งานจริงในทีม/องค์กร **ควรทำ backend proxy เล็ก ๆ** (เช่น Azure Function / Cloudflare Worker) แทนการฝังคีย์ในไคลเอนต์
2. **โหมด real-time ขึ้นกับ Chromium** — ใช้ไม่ได้บน Word for Mac (ดูหัวข้อข้อจำกัดด้านบน) และขึ้นกับเสถียรภาพ/นโยบายของบริการฟรีของ Google ซึ่งอาจเปลี่ยนแปลงได้โดยไม่แจ้งล่วงหน้า เพราะไม่ใช่ API ที่มี SLA รับประกัน
3. **ค่าใช้จ่าย (เฉพาะโหมดอัปโหลดไฟล์)** — ทุกครั้งที่ถอดเสียงคือการเรียก OpenAI API ซึ่งมีค่าใช้จ่ายต่อนาทีของเสียง ควรประเมินปริมาณการใช้งานก่อน deploy จริง
4. **ข้อจำกัดขนาดไฟล์ (โหมดอัปโหลด)** — endpoint นี้รับไฟล์สูงสุด 25MB ต่อการเรียกหนึ่งครั้ง ไฟล์เสียงยาวมากต้องตัดแบ่งก่อนอัปโหลด (ยังไม่ได้ทำใน MVP นี้)
5. **ไอคอนใน `assets/` เป็นไอคอนตัวอย่าง** ควรเปลี่ยนเป็นไอคอนจริงก่อนเผยแพร่

## แนวทางอัปเกรดที่แนะนำ (ถ้าจะใช้งานจริงระยะยาว)
- เพิ่ม backend proxy ตามข้อ 1
- แบ่งไฟล์เสียงยาว ๆ เป็นท่อน ๆ อัตโนมัติ (ffmpeg.wasm ฝั่ง client หรือ backend) แล้ววนถอดเสียงทีละท่อน
- เพิ่ม UI เลือกจุดแทรกข้อความ (เคอร์เซอร์ปัจจุบัน / ท้ายเอกสาร)
- แคช/บันทึกประวัติการถอดเสียงไว้ตรวจทานย้อนหลัง
